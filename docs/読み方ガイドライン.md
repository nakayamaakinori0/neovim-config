# 読み方ガイドライン

この設定を理解するための読む順番と、知りたいことからファイルを引く方法をまとめる。構造の説明は [ARCHITECTURE.md](ARCHITECTURE.md) にある。

## 1. 読む順番（合計 約 40 分）

| 順 | ファイル | 時間 | わかること |
|---|---|---|---|
| 1 | [ARCHITECTURE.md](ARCHITECTURE.md) | 10 分 | 全体の構造。本体とプラグインの分担 |
| 2 | `init.lua` | 1 分 | 読み込み順 |
| 3 | `lua/config/plugins.lua` | 5 分 | 入っているプラグインと build の仕組み |
| 4 | `lua/config/lsp.lua` | 5 分 | LSP サーバーと補完。いちばん込み入っているのは ts_ls と Vue の部分 |
| 5 | `lua/config/keymaps.lua` | 10 分 | 使えるキー。上から「独自のキー → 本体の操作 → プラグイン → LSP」の順 |
| 6 | `lua/config/options.lua`、`autocmds.lua` | 5 分 | 細かい動き。ここは必要になってから読めばよい |
| 7 | `lua/plugins/*.lua` | 必要なときだけ | 各プラグインの設定。どれも 30 行以内 |

なぜその形にしたのかを知りたいときは `docs/specs/` を読む。0001 が今の形の土台で、0002 と 0003 は差分。

## 2. 知りたいことから引く

| 知りたいこと | 見る場所 |
|---|---|
| このキーは何をするか | `keymaps.lua` を検索する。本体の標準キーなら `:h <キー>`（例: `:h ]b`） |
| このオプションはどこで設定したか | `options.lua`。なければ本体の既定値 |
| このプラグインは何のために入っているか | `plugins/<name>.lua` の 1 行目のコメント、または README のプラグイン表 |
| LSP が動かない | `lsp.lua` と、ARCHITECTURE.md の 5 章の「制約」 |
| 保存したら勝手に整形された | `plugins/conform.lua`（Python 以外は保存時に整形） |
| なぜこの形にしたか | `docs/specs/` |
| 操作方法 | `docs/usage/` |

## 3. 動いている Neovim で確かめる

コードを読むより早く答えが出ることが多い。

| 確かめたいこと | コマンド |
|---|---|
| キーの割り当てと、どのファイルで設定したか | `:verbose map <キー>`（例: `:verbose map <leader>e`） |
| オプションの値と、どこで設定したか | `:verbose set <オプション>?`（例: `:verbose set shiftwidth?`） |
| `<leader>` で始まるキーの一覧 | `<Space>` を押して待つ（which-key が出る） |
| LSP がつながっているか | `:checkhealth vim.lsp` |
| プラグインが入っているか | `:lua =vim.pack.get()` |
| 全体の健康診断 | `:checkhealth` |
| 本体機能の説明 | `:h vim.pack`、`:h lsp-config`、`:h lsp-completion`、`:h treesitter`、`:h netrw` |

## 4. 読むときの注意

- **キーマップは keymaps.lua にしかない。** `plugins/*.lua` にキーマップを探しに行かなくてよい
- **プラグインのキーは押したときに読み込む。** keymaps.lua の `function() require(...) end` は、プラグインより先に読まれても動くための書き方で、遅延読み込みではない
- **LSP のキーは LSP がつながったバッファにしかない。** Markdown などで `gd` が本体の動き（その場の定義へ移動）になるのは正常
- **nvim-lspconfig の `setup()` は使っていない。** サーバーの既定値は、このプラグインの `lsp/<server>.lua` を本体が読んでいる。既定値を見たいときは `~/.local/share/nvim/site/pack/core/opt/nvim-lspconfig/lsp/` を開く
- **nvim-treesitter はパーサーを入れるだけ。** ハイライトは `plugins/treesitter.lua` の FileType autocmd が本体の `vim.treesitter.start()` を呼んでいる
